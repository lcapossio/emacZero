# emaczero Linux driver benchmark, 2026-10-26

ZCU106 (xczu7ev, 4x Cortex-A53 at 1.2 GHz), Linux 6.12.60 (linux-xlnx, PREEMPT_NONE, HZ=250, CONFIG_PAGE_POOL=y), emacz_zephyr zcu106_r5 block design rebuilt with the MAC's checksum offload (TX_CSUM_OFFLOAD=1, RX_CSUM_OFFLOAD=1; CAPS reads 0x05EE0006): emacZero rev 2 behind an AXI DMA 7.1 (SG, 32-bit memory side, no DRE) at 150 MHz, non-coherent. Link: 1000BASE-X over fibre to a PC SFP port. Driver defaults: RX ring 128 (page pool, two buffers per page), TX ring 64, SG, TX checksum by the MAC's inserter for TCP and UDP (software for frames outside its scope), RX checksums verified by the MAC's checker, threaded NAPI, no RPS, DMA interrupt affinity left at the default. The board's iperf3 server pinned to CPU2. Host: Windows 11 PC, iperf3 in WSL2.

Board: 6.12.60, driver: emaczero, version: 6.12.60; counters read over the serial console

Note added later: the MAC's TX inserter was the driver's default when this was recorded. It is now behind the private flag mac-tx-csum, off by default, so these results correspond to `ethtool --set-priv-flags eth1 mac-tx-csum on`. With it off, TX checksums are summed in software during the bounce copy, as in the 2026-10-25 threaded record.

Host: iperf 3.16 (cJSON 1.7.15); 10 s per test unless stated
