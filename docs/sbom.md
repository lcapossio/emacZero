# SBOM Guidance

Each GitHub release carries one CycloneDX 1.5 JSON SBOM per FuseSoC target in
`emaczero.core` (`emaczero-<tag>-<target>.cdx.json`), generated by
`sw/gen_sbom.py` and attached by the `release-sbom` workflow
(`.github/workflows/release.yml`) when the release is published. Use the SBOM
of the target you build. For a commit that is not a release, generate it
yourself:

```sh
python sw/gen_sbom.py --out sbom/                 # one SBOM per target
python sw/gen_sbom.py --target default --out sbom/
pip install -r .github/requirements/sbom.txt
python sw/validate_sbom.py sbom/*.cdx.json        # CycloneDX 1.5 schema, strict
```

Each SBOM lists the files of that target's filesets plus the files they
`` `include `` (`rtl/version.vh`), each with its SHA-256 and the SPDX licence
from its header. The `default`, `with_l3` and `vhdl` targets are the core
RTL; the `arty_a7` target also lists the Arty A7 board RTL
(`fpga/arty_a7/rtl/`) and its constraints (`arty_a7.xdc`). Files are read
from the commit, not the working tree, so the hashes are those of the files
as committed (LF line endings) whatever the checkout's line endings or local
edits.

The version is the tag given with `--version` (the release workflow passes the
release tag, and the script fails if that tag does not point at the commit),
else the tag on HEAD (the highest in version order if there are several),
else the full commit hash. The package URL is
`pkg:github/lcapossio/emaczero@<version>`, lowercase and with the version
percent-encoded, as the purl spec asks. File names percent-encode the version
too, so a tag such as `release/v1` stays one file name.

The output is deterministic: the timestamp is the commit time in UTC and the
serial number is derived from the package URL and target, so the same commit
and version always give the same files. The generator records its own commit
as the tool version, which differs from the described commit when it
describes an older tag (`--root`). `build_and_test.py` phase 0e runs
`gen_sbom.py --check`, which reads the working tree (so it also sees files not
committed yet) and fails when a listed file is missing or has no SPDX header.

The rest of this file is the component-inventory guide for what the generated
SBOMs do not cover (software, the ZCU106 board port, verification and build
scripts) and for integrators who build their own SBOM.

## Recommended Format

Use CycloneDX JSON or SPDX 2.3. For RTL-centric products, include the HDL
source files of the selected target configuration, plus any scripts,
simulation models, generated files, and third-party IP that the product's
build or evidence flow uses.

Recommended component coordinates:

- Supplier: `bard0 design` (GitHub owner `lcapossio`)
- Component name: `emacZero`
- Component type: `library`
- Version: release tag, such as `v0.2.0`, or the full commit hash when no tag is
  used. The VERSION CSR (`0x00`) reads `0x0002454D` for `v0.2.x`.
- Licence: `Apache-2.0`
- Primary package URL, if supported by the SBOM tool:
  `pkg:github/lcapossio/emaczero@v0.2.0` (purl names are lowercase)
- FuseSoC VLNV: `bard0:eth:emaczero:0.2.0`

## Inventory Scope

The FuseSoC core file `emaczero.core` is the authoritative list of HDL files
per configuration: the `default` target uses the `rtl_core` fileset,
`with_l3` adds the optional L3 helpers in `rtl_l3`, and `vhdl` uses the VHDL
port (`rtl_vhdl_target` and `rtl_vhdl_core`) instead of `rtl_core`. List the files of the
target you build, not the whole repository.

| Area | Include | Notes |
|------|---------|-------|
| MAC RTL | `rtl/` per the `rtl_core` fileset, plus `rtl/version.vh` | Core MAC, PHY interfaces, CSR, CDC/FIFO, checksum offload. |
| Optional L3 RTL | `rtl/net/` per the `rtl_l3` fileset | Demo ICMP/UDP helpers; only when built. |
| VHDL port | `rtl/vhdl/` per the `rtl_vhdl_core` fileset, plus the one `rtl/vhdl/target/` package you build with | VHDL-93 translation of the MAC RTL; list it instead of `rtl_core` when you build the VHDL. |
| Software | `sw/emaczero/` | C register map and driver helpers, if the product uses them. |
| LiteX wrapper | `litex_emaczero/` | Only for LiteX-based products. |
| Board ports | `fpga/arty_a7/`, `fpga/zcu106/` | Reference designs, not part of the core. The ZCU106 port generates AMD's 1G/2.5G Ethernet PCS/PMA IP at build time; list it as third-party IP if a product reuses that port. |
| Debug submodule | `fcapz` (fpgacapZero, pinned by the submodule commit) | Used only by the board debug builds, never by the core. |
| Verification | `build_and_test.py`, `sim/tb/`, `sim/cocotb/`, `sim/parity/`, `tests/` | Executable verification intent and evidence. `sim/parity/` holds the formal equivalence manifests of the VHDL port. |
| Build scripts | `fpga/*/scripts/`, `fpga/scripts/` | Synthesis, implementation, and hardware-test flows. |
| Documentation | `README.md`, `SECURITY.md`, `CHANGELOG.md`, `docs/` | Integration, security, register, and evidence guidance. |
| Examples | `examples/` | Only examples used by the downstream product or evidence flow. |

The core has no third-party HDL dependencies. The formal proofs of the VHDL
port use [translateHDL](https://github.com/lcapossio/translateHDL), a
verification tool that is not part of any build; CI pins its commit. On Xilinx targets the DDR I/O
wrappers (`ddr_input`, `ddr_output`) instantiate vendor primitives (`IDDR`,
`ODDR`, `IDDRE1`, `ODDRE1`) that come from the synthesis tool's library.

Do not list host operating system packages, FPGA vendor tools, Python
installations, WSL distributions, or board files as emacZero components unless
they are vendored into the repository. Record those, with their versions, as
product build-environment dependencies instead; the synthesis tool version
matters for RTL because it produces the bitstream.

## Release Evidence

For each downstream integration, retain:

- The release tag or full commit hash.
- The generated SBOM file and tool/version used to create it.
- `python build_and_test.py` output, including Verilator PHASE 0b status (each
  GitHub release from `v0.2.0` carries this log for its commit).
- Synthesis, implementation, timing, and hardware-test logs for the target
  FPGA, PHY mode, and parameter set.
- Any local patches applied after the tagged release.

The `v0.2.0` SBOMs describe that tag's `emaczero.core`, which did not list
`rtl/mii_tx_saf.v` (fixed after the release; see `CHANGELOG.md`). A `v0.2.0`
build of the default MII path also uses that file.

## Open Work

- Define whether generated diagrams, logs, and vendor output products are
  included in release SBOMs or stored only as evidence artifacts.
- The SBOMs cover the files of each FuseSoC target only: the core RTL, and for
  `arty_a7` the Arty board RTL and constraints. Software (`sw/emaczero/`), the
  LiteX wrapper, the ZCU106 port, build scripts and the board debug submodule
  are not in them.
